# <type>(<scope>): <subject> (50자 이하로 요약, 마침표 생략)
# 예: feat(home): 메인 대시보드 UI 구현
# 예: fix(ecg-read): BBox 좌표 역변환 NaN 예외 처리

# --- 본문 작성 영역 (아래에 빈 행을 한 줄 두고 내용을 입력해 주세요.) ---
# 무엇을(What), 왜(Why) 변경했는지 작성해 주세요.

# ----------------- Git 커밋 컨벤션 가이드 -----------------
# 1. type은 소문자로 작성합니다.
# 2. scope는 변경 대상 모듈/기능 영역을 소괄호로 감쌉니다. (선택)
# 3. subject는 명령문으로 작성하고 끝에 마침표(.)를 사용하지 마십시오.
# 4. 제목과 본문 사이에는 반드시 1칸의 빈 줄을 두십시오.
# 5. 타입(type) 규칙 (Conventional Commits):
#    - feat     : 새로운 기능 추가
#    - fix      : 버그/오류 수정
#    - docs     : 문서 변경 및 수정 (README.md, 주석 등)
#    - style    : 코드 포맷팅, 세미콜론 누락, 미사용 임포트 정리 (로직 영향 없음)
#    - refactor : 코드 리팩토링 (기능 추가나 오류 수정 없음)
#    - test     : 테스트 코드 추가 및 수정 (프로덕션 로직 변경 없음)
#    - chore    : 빌드 설정 변경, 의존성 패키지 관리, 리소스 파일 추가 등
#    - build    : 빌드 시스템 또는 외부 의존성 변경 (gradle, libs.versions.toml 등)
#    - ci       : CI/CD 설정 변경
#    - perf     : 성능 개선
#    - revert   : 이전 커밋 되돌리기
